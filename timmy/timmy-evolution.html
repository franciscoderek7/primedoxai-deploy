How this actually works (read me first)

Every rule below starts with a score of 0. Every time a rule fires and you find out whether it was right, you log that as an outcome — a reward signal. Blocking a real threat is worth +1. A false positive costs -2 — deliberately worse, because one false alarm burns more trust than one quiet correct block earns. Missing a real threat costs -3 — the worst outcome of all.

Timmy is a static rule scorer, not a self-modifying AI. When a score crosses a lifecycle threshold — Sandbox → Active → Core Policy, or any of those → Disabled — Timmy does not make that change. It raises a pending suggestion in the "Needs your approval" panel and stops. Nothing about a rule's pattern, action, or enforcement changes until you click Approve. A Core rule that regresses still only gets flagged for your review, exactly like before — reaffirm or retire it yourself.

Nobody is hand-editing the scores — the scoreboard does that part automatically. But every actual change to what Timmy enforces is a human decision. See engine/rl-rule-engine.js for the source (the approveSuggestion / dismissSuggestion methods are the only ones that ever change a rule's status), and the bottom of this page's sibling file for how the exact same engine — same file, just a different name — runs PrimeDox AI's own rule lab too.
